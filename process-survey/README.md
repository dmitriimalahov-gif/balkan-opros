# Опрос «Карта процессов Balkan»

Публичная анкета для сотрудников: ИИ-интервью о рабочих процессах (RU/RO) с вариантами ответов и своим текстом.
Без регистрации и приглашений; каждый видит только своё интервью. Панель руководителя — по паролю.

- Анкета: `<публичный адрес>/`, панель: `<публичный адрес>/admin` (адрес — `./start.sh status` или вкладка «Ссылка и приглашение»).
- Пароль панели: `ADMIN_PASSWORD.txt` (создаётся при первом запуске, права 600). Сменить — записать новый и перезапустить сервер.
- ИИ-помощник, интервьюер, резюме и сводный анализ: `qwen3.8-flash-next-iq3_s` через OpenAI-совместимый API. Локальная Ollama используется только как аварийный резерв при недоступности API. Если и она недоступна, анкета идёт по готовым вопросам с вариантами.
- Разбор документов: основная модель `qwen3.8-flash-next-iq3_s` через OpenAI-совместимый API. Ключ читается только сервером из `run/llm.env` с правами 600 и не попадает в браузер, SQLite или экспорт. При недоступности API выполняется резервный разбор через локальную Ollama; при её сбое сохраняются текст и структура документа.
- Данные: `data/survey.db` (SQLite). Токен респондента хранится только как sha256.

## Ролевые сценарии

- На старте сотрудник выбирает одну или несколько из 22 функций. Первая — основная, остальные — дополнительные. Отдел задаёт безопасное значение по умолчанию. Для старых интервью функция определяется по отделу, а `roleKeys` содержит одну роль.
- Свободное поле `about` необязательно: сотрудник описывает работу своими словами. `about_analysis.py` извлекает только подтверждённые текстом занятия, системы и документы; локальная модель уточняет их без новых обязанностей, а при сбое работает словарный анализ. Вопросы ранжируются по релевантности внутри этапа без потери обязательных тем. В ERP экспортируются `about` и `about_analysis`.
- `role_packs.json` — единый источник: назначение, международные ориентиры, ответственность, решения, документы, KPI, обязательные темы и 14 вопросов на русском и румынском для каждой функции. Всего 308 вопросов.
- ИИ использует вопросы как каркас и уточняет фактическую работу, полномочия, документы, исключения и доказательства. Резервная анкета проходит те же 14 тем, затем общие стыки и улучшения.
- В сообщениях хранится `questionKey`; карточка руководителя показывает покрытие тем. Резюме содержит `responsibilities`, `decision_rights`, `documents`, `kpis`, `exceptions` и `erp_requirements`.
- Экспорт ERP №2 дополнительно содержит `role_key`, `role_keys`, `role_title` и `role_coverage`; при нескольких функциях темы и покрытие объединяются. Полный справочник формируется `python3 render_role_guide.py` в `exports/`.
- Акцент интерфейса — фирменный синий `#21439B`; логотип Balkan встроен в собранную страницу и не требует внешнего запроса.

## Голос интервьюера и голосовые ответы

- Озвучка интервьюера использует локальный Qwen3-TTS и тот же профиль `dmitrii` / `numerom-dmitrii-v2-clean`, что и NumerOM. Браузерный SpeechSynthesis не используется и чужой голос автоматически не подставляется.
- На первой странице через 2 секунды после загрузки запускается короткое приветствие голосом владельца на языке интерфейса. `/api/welcome-voice` обслуживает только две фиксированные фразы RU/RO и кэширует их. Приветствие останавливается динамиком, сменой языка или началом интервью; если браузер запрещает автозапуск звука, предлагается ручной запуск.
- Озвучка по умолчанию выключена. При включении сервер заранее ставит в очередь текущий вопрос и два следующих готовых вопроса, а текущий запускается через 2 секунды после появления на странице. Вся старая история подряд не читается. Кнопка у сообщения запускает или останавливает его сразу; таймер отменяется ответом, выключением звука, выходом или включением микрофона. Повторное прослушивание использует кэш.
- `voice_worker.py` работает в голосовом окружении NumerOM и использует его эталон, модель, очистку, темп 1,2 и общую блокировку тяжёлых задач. `start.sh` запускает его вместе с сервером; `watchdog.sh` перезапускает при остановке.
- API принимает только индекс уже сохранённого сообщения интервьюера из интервью сотрудника: произвольный текст для синтеза передать нельзя. `/api/me/voice-prefetch` рассчитывает два следующих вопроса на сервере по ролям и персональному приоритету; для динамического ИИ-ответа предзагружается сам ответ. Готовые M4A-файлы хранятся локально в `data/voice/clips/<hash>/`, не добавляются в сообщения, вложения или JSON экспорта ERP.
- Для RU и RO выполняется обратная проверка Whisper, до трёх вариантов генерации и повтор при пустом фрагменте. Русские числительные приводятся к единой форме («три–пять» = «3–5»), чтобы правильное произношение не отклонялось. Румынский использует итальянскую языковую подсказку, фонетическую запись только для синтеза и короткие смысловые фрагменты; правильность проверяется по исходному румынскому тексту. Аудио выше порога расхождения не выдаётся как готовое; автоматическая проверка не заменяет прослушивание человеком.
- Голосовой ввод использует браузерный SpeechRecognition. Микрофон включается только по кнопке «Ответить голосом», запись ограничена 120 секундами и останавливается вручную, при отправке ответа или выходе из интервью.
- Распознанный текст добавляется в поле ответа, сохраняется в черновике и может быть исправлен перед отправкой. Аудио микрофона не записывается в сообщения или вложения и на сервер не передаётся: сохраняется только итоговый текст. Речь может обрабатываться сервисом браузера, поэтому секреты произносить не следует.
- Постоянная страница разрешает микрофон встроенному опросу через Permissions Policy (`allow="microphone"`). Это не даёт автоматического доступа: сотрудник всё равно нажимает кнопку и подтверждает разрешение браузера.

## Скорость интервьюера и мобильный экран

- На каждом шаге передаются только три ближайшие ролевые темы, краткая инструкция и последние 12 сообщений. Для интервью используются `reasoning_effort=low`, `max_tokens=700` и таймаут 60 секунд; сложный анализ и JSON-резюме сохраняют обычный режим.
- На мобильном экране панель ответа находится под вопросом, ограничена 52dvh и прокручивается внутри себя. Новый вопрос прокручивается к началу с учётом шапки, поэтому варианты не перекрывают его.

## Материалы к вопросам

- К каждому вопросу сотрудник может приложить до 5 материалов: Excel/CSV, PDF, Word, изображения или HTTPS-ссылку на Google Таблицу. Один файл — до 500 МБ; загрузка идёт частями по 8 МБ с повтором при сбое сети.
- Файлы хранятся в `data/attachments/<interviewId>/<attachmentId>`, а метаданные и связь с вопросом и ответом — в SQLite. Лимит — 100 материалов и 5 ГиБ файлов на интервью.
- Руководитель видит и скачивает материалы в карточке сотрудника. JSON-экспорт для ERP №2 содержит метаданные и SHA-256, но не встраивает сами файлы в JSON.
- Сразу после загрузки `knowledge.py` ставит документ в локальную очередь. В `knowledge_documents` сохраняются статус, извлечённый текст, структура таблиц, поля, резюме, процессы и связи. Excel/CSV читаются через openpyxl/pandas, PDF — через pypdf/pdftotext, Word — через python-docx/textutil, изображения и сканы — через macOS Vision. Публичная Google Таблица разбирается через CSV-экспорт; закрытая ссылка получает понятный статус ошибки.
- Резюме, поля и связи формирует настроенная серверная модель; текст документа отправляется на указанный API только после подключения владельца. Если и она, и резервная локальная Ollama недоступны, исходный текст и структура всё равно сохраняются со статусом `extracted`; при ошибке разбора интервью не зависает, а карточка показывает причину.
- Отправка ответа ждёт окончания разбора с числовым прогрессом, затем автоматически открывает следующий вопрос. Резюме документов доступно интервьюеру в следующем запросе к модели.
- Вкладка «База знаний» в панели руководителя содержит поиск по содержимому, карточки анализа и исходный текст для проверки. Экспорт ERP №2 дополнительно включает массив `knowledge_documents`.

## Управление

```bash
./start.sh start            # сервер 127.0.0.1:8795 + работник голоса + туннель Cloudflare + сторож
./start.sh status           # что запущено и текущий адрес
./start.sh restart-tunnel   # новый адрес
./start.sh stop
./install-autostart.sh      # автозапуск после перезагрузки Mac (remove — выключить)
```

## Постоянная ссылка (как у Helper)

**https://dmitriimalahov-gif.github.io/balkan-opros/** — её и раздавать сотрудникам; панель: тот же адрес + `#admin`.

Туннель временный (quick tunnel, живёт около суток). Сторож (`watchdog.sh`, раз в 2 мин) при 3 сбоях подряд поднимает
новый туннель; новый адрес пишет в `pages/current.json` и отправляет в репозиторий
[dmitriimalahov-gif/balkan-opros](https://github.com/dmitriimalahov-gif/balkan-opros) (GitHub Pages, ~30–40 с).
`pages/index.html` встраивает опрос во весь экран и хранит ключ сотрудника на постоянном адресе (postMessage), поэтому
незаконченные интервью переживают смену туннеля. Пока адрес обновляется (2–5 мин), страница пишет «Опрос временно
недоступен» и повторяет попытку сама. Последний опубликованный адрес — `run/pushed-url`; ответы в репозиторий не попадают.
`sync-code.sh` запускается независимым LaunchAgent `com.balkan.process-survey-code-sync` раз в 2 минуты: копирует исходный код
в `pages/process-survey/`, прогоняет все тесты и только затем создаёт коммит и отправляет его в `main`. Агент не запускает опрос
или туннель на Mac и не меняет `current.json`. Установка — `./install-code-sync-autostart.sh`, состояние — с аргументом `status`,
отключение — с аргументом `stop`. Пароли, API-ключи, `data/`, `exports/` и рабочие файлы `run/` исключены; при ошибке теста,
конфликте веток или признаках секрета публикация кода останавливается. Журнал — `run/code-sync.log`.
При сбое на Mac появляется уведомление с этапом ошибки; одна и та же ошибка показывается один раз до восстановления.

Сторож постоянного сервера `monitor-server.sh` (LaunchAgent `com.balkan.process-survey-server-monitor`, раз в 5 минут)
проверяет `https://poll.erp.numer.om/healthz` и отдельно ИИ-модель интервьюера: `/healthz` её падения не видит, потому что
резерв держит `"ai": true`. Модель проверяется без ключа: 401/404 — работает, 5xx или нет ответа — не работает. После 2 сбоев
подряд на Mac приходит одно уведомление, при восстановлении — ещё одно; без интернета на Mac проверка пропускается.
Установка — `./install-server-monitor-autostart.sh`, аргументы `status` и `stop`; журнал — `run/server-monitor.log`.

Варианты ответа: в любом вопросе можно отметить несколько и дописать свой текст (решение владельца 31.10) —
страница игнорирует режим `one`, промпт ИИ разрешает только `[[OPTIONS many: …]]`.

Тема: по умолчанию светлая (системная тёмная тема не применяется), переключатель луна/солнце в шапке. Выбор хранится
на постоянной странице (`bp_theme`) и передаётся опросу параметром `#th=`, поэтому переживает смену туннеля.

## Устройство

- `server.py` — HTTP + API + промпты (интервьюер, резюме, анализ) + ограничения частоты. Только stdlib.
- `static/index.html` — собирается `build_index.py` из `source/karta-processov.artifact.html`
  (страница-артефакт claude.ai https://claude.ai/artifact/NfdAuiQXqtPeLVn1HsQyBU, слой `window.claude` заменён на API).
  Правки страницы: менять исходник, затем `python3 build_index.py source/karta-processov.artifact.html`.
